## 本地实现补充决定（2026-10-25，用户已授权自行处理新问题）

### D-13：保留质量改变时 alternate payoff / gift 的尺度

Algorithm 12 第 16/19/25/27 行使用保留质量 D；§2 定义的 counterfactual value 却按完整旧信息集的质量 q 归一。Appendix C.2/Figure 3 明确说删去另一半分支后 alternate payoff 要放大。实现采用 `alternate = V_old * q/D`、`gift = G_old * q/D`，A 的 chance 和被删分支 B 同时按 D 处理。只缩放 A、遗漏分支而保持 alternate 不变，会使“旧策略原 margin 为零”的情况变为非零。独立二分支测试以及 Appendix C 重建通过；这补全了伪代码未写明的尺度，不能声称作者实际代码已核实。保留原质量的另一种算法会改变 margin 权重，不混入主版本。

### D-14：Figure 1–3 / Appendix C 的具体算术不一致

已目视复核 P1 p.7、p.15，图的叶收益、均匀 nature 和均匀 blueprint 给中央 C2' 的归一化旧值 `min((2+3)/4,(3+2)/4)=5/4`；印刷值为 5/2。保留 n=2、删除 n=3 后，按 D-13 放大两倍为 5/2，印刷图和 B 表为 5；C.2 正文另写 3。C.1 对 C4' 正文写 2，图和表为 1/2，计算也为 1/2。采用定义和叶收益推导出的值，保留印刷值到 `results/integration/small-games.json` 的 discrepancy 字段。遗漏 n=3 的 H/T 贡献仍为 3/2、1，与原文一致。由此旧均匀 blueprint 的 margin 恰为零。解释为原文算术/归一化不一致，存在未披露约定的可能，不能将所有印刷数字强行视为同一自洽模型。

### D-15：普通 Stockfish 无法搜索的 FoW 王受攻局面

缺王先按真正 FoW 终局给 ±1/±6，不送入 UCI。若**非行动方的王已被当前行动方攻击**（包括双王相邻、双王受攻），普通 Stockfish 不接受该标准棋非法输入；FoW 中当前方有一步吃王，使用当前行动方视角 +0.9，换到固定我方视角并按 variant 缩放。此项是非终局叶启发式，真正展开吃王后才给终局值。其他有效 cp/mate 沿用 D-07，普通 stalemate 的引擎 0 分不终止 FoW。原始/加速引擎的专门输入探针已覆盖这些类别；作者是否修改过 Stockfish 未知，此适配不能视为其原实现。

### D-16：u_hat 的 continuation B 与零 joint reach

Algorithm 15 第 13 行的旧 continuation 使用匹配旧 x/y、候选根与其续树，并包括当前切点之后会保留的 B 项。过去切点之前的 alternate/信息支付不重新计入续局；不能把矩阵 B 当作带有隐式 chance 权重的叶值。实现以旧 joint reach 条件化 A 和相应 B；零 joint reach 但正 counterfactual reach 时，用 `p*x` 的根权重、旧策略在切点后的条件策略重建；零概率父序列的条件策略采用显式均匀约定，trace 标记 `counterfactual_reach_zero_joint_boundary`。这属于论文没有展开的零概率边界，不声称该分支的经验概率已知。零 counterfactual reach / 零 D 仍显式失败，不加 epsilon。下游 B、生效范围以及偏离旧 y=0 的独立小树测试已通过。

### D-17：完整 I 的原生加速与代表历史

Python 参考与 C++ 内核都枚举并保留全部不同候选局面。C++ 用 reservoir sampling 在同一局面的兼容候选历史中选一个完整代表，分布等价于 D-09 的均匀 shuffle 后取首个，但 PRNG 和具体轨迹不同，不能声称两个 backend 在同种子下逐位一致。选中历史不是拼接历史；根补样仍是无放回、均匀的 `min(max(0,200-|R|),|I\R|)`，不会截断超过 200 的保留根。观察/行动/转移、候选集合、代表历史可回放和 deadline 原子提交已交叉验证；571,654 个局面的规模探针没有改为粒子滤波。尚未验证 10^7 局面的资源消耗。

### D-18：时间与浮点工程边界

正式入口严格从行动权交接计时，8 秒包含更新和等待。为回滚、对象释放、策略采样及提交预留 1 秒；双方相同，可提前返回。序列构建、LP 和引擎调用有 deadline；未通过证书的扩展不能提交。超时后的旧 snapshot 只指**当前这次决策**已有的有效解，没有就失败。原 .3 秒预留在探针中出现迟交，已保留失败记录并扩大预留，未偷偷放宽 8 秒。浮点 LP 出现容差内负 realization weight 时，重建非负条件分布并正向恢复流，再重新检查流、全部 A+B 的不等式及 gap ≤1e-8；不能只剪负值后放行，也不删正的小概率。模式 epsilon 仍固定 1e-15，support 仍严格 >1e-9。

### D-19：引擎重置优化和共享 HiGHS 状态

SF13 v4 使用等效的 TT 脏区清零和 history epoch 初始化，不保留跨独立查询的搜索知识；完整修改源、构建命令和有限等价性证据见集成记录。错误 SIMD 版本已经拒用。HiGHS 有进程级 scheduler，旧共享测试先以默认线程数调用会使后续 `threads=1` 求解返回 `Not Set`；本实现串行 LP 在调用前重置 scheduler，保持实际单线程。所用内部接口随 SciPy 版本冻结，全部相关 470 个测试已合跑通过，原失败报告保留。

### D-20：仅在 Stockfish 输入中移除标准棋非法的 en passant 标记

双颜色 pilot-v8 在假设局面 `r3k1nr/p1p2ppp/8/1pP1n3/2PP2b1/8/PP3PPP/RNBK1B1R w kq b6 0 1` 触发引擎退出。白王 d1 被象 g4 将军，c5b6 的 FoW en passant 不解除该将军；此历史在普通棋不可能出现。原始未修改 SF13 与优化 v4 均在此 FEN 崩溃，去掉仅对标准棋不可用的 EP 标记后，两者均返回 cp=630、depth=1、nodes=43，证据保存于 `engine-ep-crash-isolation.json`。因此增加独立 UCI 输入转换：没有标准棋合法 EP 时清除 EP，保留正常合法 EP；这不改变送入 SF 的标准棋合法动作集合。FoW 规则、候选局面键、历史、实际行动和玩家可见 EP 均保留原有效标记，不使用该转换。测试覆盖输入不变、两种合法动作集合相等和 UCI 参数。此项是本项目的 SF 兼容处理，作者处理方式仍未知；引擎其他异常仍显式失败，不以任意估值或自动重启掩盖。

### D-21：补全 SF13 对 FoW 特有多重将军输入的王步检查

正式首批第 3 局在第 24 ply 的假设局面 `r1bnr1k1/pp3ppp/5n2/2N5/8/P7/1P2K1PP/R1B1qB1R w - - 0 1` 崩溃；原始和 v4 均可独立复现。e1 后与 e8 车从相反方向攻击 e2 王，是普通棋不可达的多重将军。原始 `movegen.cpp` 的 EVASIONS 用射线排除王步，但排除了所有 checker 所占格；`Position::legal` 又在王的原格仍占用时检查目标攻击，错误允许沿另一将军射线吃 checker，随后搜索进入非法状态。`Position::pseudo_legal` 本来已使用移走王的完整攻击检查，说明该补全有原实现依据。

### D-22：等价预处理与实际提交余量

v5 首个完整批次 `formal-100-v2` 完成 6 局（4 胜 0 和 2 负），第 7 局在 baseline 第 21 ply 的首次 LP 前耗尽预留工作时间；不是引擎崩溃。其 I=302、补根=200，必须估值约 9000 个不同局面，不能减小 L 或删 I。重放该 baseline 的相同私有观察和补样随机流，测得冷启动 6.33 秒。

实现以下等价优化：每个 UCI 请求只生成一次 FEN，随后移至已有 C++ 内核序列化，并逐字与 Python FEN 对照；缓存可见观察的规范签名和走法字符串，求解树中的对方观察只生成相同签名而不创建用不到的 Observation 对象，历史哈希的输入和信息等价关系不变；LP 求解前代入单动作约束 `x_child=x_parent`，合并相应 A+B 系数，保留完整序列元数据。求解后恢复全部 realization weights，再对原始完整 A+B 做独立树 best-response，重建完整 primal/dual 界和流证书。残差、gap 仍须 ≤1e-8；没有改变量化阈值、M、根数量或 payoff。

小博弈对比未消元 LP、带 B/辅助序列案例以及全套 481 项测试通过；500 个局面的 FEN、观察和签名与独立 Python 实现一致。1452 次 Stockfish 评估与序列化优化前逐项相同。失败回合从 6.33 秒依次降至 5.25、4.03、3.70 秒，所选 `d7d1` 和 value=-0.08506781706733674 一致。报告为 `baseline-cold-v5-*.json`。消元与浮点累加顺序可能改变多解博弈中返回的某个最优策略；不宣称墙钟对局逐位不变。

旧批次成功提交的最大耗时为 7.963 秒，完整保留根曾达到 2481，证明 L=200 不是上限，也说明大型事务回滚/释放需要余量。双方仍采用 8 秒总期限：首次有效求解截止于总期限前 1 秒，后续迭代截止于总期限前 2 秒，留给回滚、释放和策略提交。若首次求解失败仍显式失败；不改用随机行动。此项覆盖 D-18 的统一 1 秒预留细节，属于工程安排。已有 6 局保留并独立回放验证，不混入重新运行的单版本 100 局批次。

### D-23：及时释放搜索对象，并保留本次决策的首个有效解

`formal-100-v3` 完成 4 局（1 胜 0 和 3 负）后，第 5 局第 31 ply 的 baseline 在首次 LP 之前耗尽工作期限。重放确认完整 I=178107，200 个新根产生 10600 个不同估值局面；实际批次在进入 act 前已消耗约 1.70 秒，建树再用约 5.19 秒。不能将该失败记为负局或减小完整 I。

诊断发现 Python 自引用递归闭包与被处理的超时异常 traceback 会滞留大型搜索对象，直到循环垃圾回收才释放。将递归操作改为模块函数或显式栈，对一次性 visitor 在 finally 中解除自引用；只对已处理的预期失败清除 traceback/context/cause，并清理完成的 futures。引擎崩溃或非预期错误仍优先传播，不能被同批次的普通 deadline 掩盖。关闭循环 GC 的 weakref 探针修复前旧矩阵仍存活、须 GC 才释放；修复后立即释放。证据为 `retention-before.json`、`retention-after.json` 和对应回归测试。此修改不改变任何博弈收益、观察或候选集合。

依 D-04，如果本次决策已经取得通过证书的首个 LP 解，但后续模式转换未完成，恢复该解对应的旧 mode/B 并提交首解；记录 `initial_mode_conversion_incomplete`，不再扩展。不能因转换未完成而丢弃本次有效解，也不能回用上一回合策略。后续树扩展仍整次事务回滚。注入转换失败的测试核验策略、模式、完整矩阵证书保持一致。

首解工作截止调整为总期限前 0.5 秒，后续迭代仍在总期限前 2 秒停止，双方相同、总期限仍为 8 秒；覆盖 D-22 的首解 1 秒预留。相同私有证据及补样流的冷重放包含最后一次该方观测更新，耗时分别为 6.38、6.51 秒，动作 `a8d8`、value=-0.0673442895577763 相同；这不是全局比赛耗时复现，未包含另一 seat 的观察工作或之前引擎缓存。报告为 `baseline-second-retention-fixed-1/2.json`。完整 485 项测试通过（`pair-a-tests-v9.xml`）；v8 唯一失败是新增关键字参数后旧测试注入器未接收 kwargs，已修复测试并完整重跑。旧批次独立保留，使用新目录重新执行正式比赛。

## D-01：value transform 的值域

- 证据：D.1（P1 p.16）称 clamp 至 `[-tau, tau]`，同时写映射 `tanh(x/tau)`，tau=6 pawns。渲染页与 P3 都保留该写法。
- 判断：数学上该映射输出 `(-1, 1)`，不是 `[-tau, tau]`；属于明确文字/公式不一致。
- 状态：**复现决定已由用户于 2026-10-23 确认；本次只更新决定记录，尚未实现或完成算法验证。** 作者真实实现仍未确认。

### 已确认的主版本与对照版本

`score_pawns` 是已转换到统一收益视角的 Stockfish pawn-unit 评分；若输入是 UCI centipawn，则 `score_pawns = score_cp / 100`。两版本均固定 `tau_pawns = 6`。

| 版本 | 非终局叶估值 | 真实终局收益（胜 / 和 / 负） | 信息项分母 M |
| --- | --- | --- | --- |
| 主版本 | `tanh(score_pawns / 6)`，等价于 `tanh(score_cp / 600)` | `+1 / 0 / -1` | `10000000` |
| 对照版本 | `6 * tanh(score_pawns / 6)`，等价于 `6 * tanh(score_cp / 600)` | `+6 / 0 / -6` | `10000000` |

先由 Fog of War 裁判判定真实终局并直接返回对应收益，再对非终局调用估值。真实胜负不以普通 Stockfish 的 checkmate/mate 标识代替；非终局的 mate score 适配仍由 D-07 处理。终局端点与各版本叶估值的饱和幅度一致，双方采用相反的收益视角。

两版本保持同一个 M，不额外给信息项乘以 6，也不将 M 除以 6；因此比较的是局面收益相对于信息项的尺度敏感性，并非整个博弈的等比例缩放。各版本分别从自身收益重新计算 alternate payoff、gift 和 margin，不跨版本复用这些数值。基础收益的界不能用于裁剪整个 gadget 的收益，也不能据此保证加入信息项后的全部行动取舍。

### 判断依据与不确定性

- 主版本优先遵循 D.1 明确写出的可执行公式。对作者实际实现仅略倾向于这一解释，证据不足以认定正文值域一定是笔误。
- D.3 的信息项尺度为 `q = |I| / 10^7`：当完整信息集大小为 `10^4`、`10^5` 时，量级分别为 `0.001`、`0.01`；接近 `10^7` 时可达约 `1`。这与归一化叶估值下“平时影响较小、信息集过大时提供明显激励”的解释相容，但只是弱支持。行动间收益差与实际信息集分布未被确认，不能仅靠值域排除对照版本；`10^7` 也不是论文给出的信息集硬上限。
- 对照版本有明确的反向依据：它符合正文 `[-tau, tau]` 的值域，并在原始评分接近零时满足 `6 * tanh(score_pawns / 6) ≈ score_pawns`，保留局部 pawn 尺度。两种解释都须保留来源标记。
- alternate payoff、gift 和归一化矩阵项由基础收益派生，可能超出叶估值范围；其量级不能独立证明作者采用了哪一种变换，也不是把真实终局收益任意放大的依据。
- 在已核验的原始资料中，作者没有明确说明 Dark Chess 真实终局收益的数值编码；现有公开代码核验也未提供完整 2021 agent 实现。因此 `±1` 与 `±6` 是本项目为保持叶估值与终局一致而确认的复现约定，不是已证实的作者参数。D-02 的信息项定义和 D-07 的引擎适配仍待独立处理。

## D-02：信息惩罚、熵分布与观测时机

- 证据：D.3（P1 p.17）按 I' 的均匀根分布计算下一观测熵，惩罚为 `2^(-H(a)) |I| / M`；Algorithm 15（P1 p.21）第 20 行写奖励 `(1-2^(-H(a))) |I| / M`，第 21 行文字却说在 I 上均匀分布。
- 状态：**四项解释，以及每个 ply 后接收观测、更新 I、仅在轮到我方时求解的时序，均已由用户于 2026-10-24 确认。本次只更新决定记录，尚未实现或完成算法验证；空 I' 的恢复等边界继续由 D-03 处理。**

### 已确认的四项解释

1. 信息项按 D.3 正文作为负惩罚加入我方收益：`r_info(a) = -2^(-H(a)) * |I| / M`。对应 Algorithm 15 第 20 行的复现赋值为 `B[Ia, empty] = r_info(a)`，其中 `Ia` 是论文中的我方根行动序列；不添加 `|I|/M` 或 `1` 的常数偏移。
2. 计算观测熵时，根 h 在搜索所考虑的 I' 上均匀分布，每个根的权重为 `1/|I'|`；不改为在完整 I 上均匀，也不以求解策略给根重新赋权。惩罚因子中的 `|I|` 仍是完整当前信息集的大小，不替换成 `|I'|`。
3. “binary entropy”按以 2 为底的 Shannon entropy 解释，单位为 bits：`H(a) = -sum_o p(o|a) * log2(p(o|a))`，求和覆盖所有可能的下一观测，约定 `0*log2(0)=0`；不把观测强行合并为两个类别。
4. 在我方行动前，基于当前 I'，对每个可行的我方候选动作 a 模拟执行，按执行后立即提供给我方的观测计算 H(a)。计算时 a 尚未采取；不把刚收到的当前观测本身当作待求熵的随机量，也不把对手下一次回应后的观测合入同一个 H(a)。

沿用 D-01，两种 value transform 版本都保持 `M=10000000`，使用同一负惩罚公式；信息项不额外乘以 6。下面分别定义实际观测处理时序与行动前的熵预测，二者均已确认。

### 判断依据与剩余不确定性

- 前两项遵循 D.3 的明确叙述；与 Algorithm 15 的差异保留为来源不一致，不据此断言已确认作者实际代码。此前把伪代码正奖励列为候选主版本的建议，已由此次负惩罚决定替代。
- 固定根下，正文负惩罚与伪代码正奖励相差与动作无关的 `|I|/M`；此前讨论的去括号式 `1-2^(-H(a))*|I|/M` 则比正文多 1。它们可有相同的单次行动偏好，但 Algorithm 15 第 24/28 行按博弈值正负切换模式，且旧值参与 alternate payoff 等后续计算，不能据此宣称完整算法等价。采用负惩罚的选择已经确认；模式阈值、收益传递和归一化的一致性仍须在阶段 3 验证，不擅自通过加回常数抵消该决定。

### 第四项：实际观测与求解时序（已确认）

- 原始依据：第 2 节（P1 p.2）第 (4) 项规定双方在到达每个内部节点 h 时获得各自的 O_i(h)；Algorithm 15（P1 p.21）第 8–10 行先接收观测、按一步后继更新 I，然后才判断是否轮到自己行动。
- 已确认时序（以下均指棋局尚未终止）：我方执行已知动作 a 后，立即接收 `o_self = O_+(ha)`，更新为 `I_after_self = {ha : h in I_before, O_+(ha) = o_self}`。此时轮到对手，按第 10 行返回，不继续执行本次子博弈求解。
- 对手行动后，立即接收 `o_opp`，从上一步已经筛选过的 I_after_self 枚举可能的对手合法动作 b，更新为 `I_after_opp = {g b : g in I_after_self, b legal at g, O_+(g b) = o_opp}`。对手真实动作不作为隐藏信息直接传入 agent；筛选结果可能对应多种动作，不要求唯一反推出 b。此时轮到我方，继续第 11 行及后续步骤，构造并求解子博弈，再选择本次行动。
- 两次观测按发生顺序进入本方观测历史与回放。即使对手随后吃掉我方刚移动的棋子、使刚获得的视野消失，也必须保留第一次观测施加的历史约束；不能只凭第二次可见棋盘重新生成候选集。保留历史事实不意味着假设当时看到的对方棋子此后一直未移动。
- 第 10 行是本算法的求解触发条件，并不表示等待对手时数学上不能计算条件策略；旧搜索树可以包含对手的不同回应，而下一轮实际决策仍按收到的新观测更新后重新求解。

### H(a) 的计算定义与顺序（已确认）

- 原始依据：D.3（P1 p.17，以 `We set L = 200` 开头的段落）和 Algorithm 15 第 21 行定义执行候选动作 a 后的下一观测熵；第 20 行先计算信息项，第 39 行才实际选择并执行动作。
- 决策时已先用刚收到的观测及完整历史更新 I，再准备本轮搜索根 I'。基于非空 I'，对每个 `a in A(I)`，令 `n_a(o) = count{h in I' : O_+(ha) = o}`，则 `p_a(o) = n_a(o)/|I'|`、`H(a) = -sum_o p_a(o)*log2(p_a(o))`。这里 h 是当前可能的根状态，ha 是模拟执行 a 后的状态；模拟不改变真实棋局或当前 I。
- 将 `-2^(-H(a))*|I|/M` 写入 B 后再求解，最后选择并实际执行一个动作。I' 的补样/空集恢复及当前根信息集的引用更新按 D-03 完成后，才计算这项熵；分组所用 I' 与本轮求解所用根集合必须一致。
- 第 8–10 行的两次真实观测更新与这项一步预测相容：我方实际落子后接收即时观测、更新 I 并返回；对手回应后再次更新 I，再为下一次我方决策重新计算各候选动作的 H(a)。不需要为当前 H(a) 指定对手未来回应的分布。
- 判断修正：此前把“我方落子后观测”与“对手回应后观测”写成实际接收时机的二选一不准确。两次真实观测都必须处理；本次确认的信息惩罚则在行动前预测候选动作执行后的即时观测。该解释有上述源文依据，但作者完整实现仍未取得。`paper_2021.toml` 和实现代码本轮不变。

## D-03：粒子不足与空 I'

- 状态：**复现决定已由用户于 2026-10-24 确认：补样数量不超过剩余候选数；I' 为空时显式重建子博弈并更新根信息集引用。本次仅更新决定记录，尚未实现或完成算法验证。**

### 原始依据与判断

- D.3（P1 p.16）明确指出旧搜索树可能没有任何当前 I 中的节点，并要求从 `I\I'` 均匀、无放回抽取“至多” `L-|I'|` 个根；L 是粒子数量的补充目标/下限，论文取 `L=200`。
- Algorithm 15（P1 p.21）第 15–16 行直接指定抽样数量 `L-|I'|`，没有显式限制为剩余候选数。采用下面的最小值公式，是在正文允许的范围内尽可能补足 L 的复现约定；不是改为有放回抽样或制造重复根。
- 第 12 行在 I' 为空时令 `u_hat=+infinity`，第 19 行又使用 `-min(u_hat, u_tilde(h))`，说明该情形应继续恢复。第 14 行的 MAKE_SUBGAME 与第 39 行的行动采样仍需要有效的游戏/信息集引用，伪代码未完整说明空根恢复和引用更新。显式分支是实现补全，不据此断言作者实际代码具有相同错误；作者完整实现仍未取得。

### 已确认的补样规则

为区分补样前后，记 R 为本轮从旧搜索树保留下来、与完整当前信息集 I 一致的根集合，要求 `R subseteq I`；记补样后的根集合为 `I'_new`。

- 补充数量：`n = min(max(0, L-|R|), |I\R|)`。
- 从 `I\R` 中均匀、无放回抽取大小为 n 的集合 S，得到 `I'_new = R union S`。保留 R 及可以复用的已有搜索内容；完整 I 不因补样而被替换或截断。
- 候选不足时纳入全部剩余候选；`R=I` 时不补样；`|R|>=L` 时不补样，也不为了满足 L 而删除已保留根。由此 `|I'_new| = max(|R|, min(L, |I|))`。
- 均匀性要求针对新增集合 S；保留旧根后形成的整个 I'_new 不必是 I 的一次全新均匀样本。D-02 在本轮 I'_new 上另行采用均匀根权重计算熵，两者不可混淆。

### 已确认的空根恢复与引用更新

1. 若 `R=empty` 且 `I` 非空，显式建立新的子博弈骨架，抽取 `min(L, |I|)` 个根；不把空 R 传入要求有效旧根信息集的普通重根流程。
2. 所有采样根按相同的本方观测历史组成同一个我方根信息集。遵循 D.3 对新增根的建模假设：对手知道具体根 h，而我方不知道；不得按隐藏根身份拆出不同的我方行动策略。
3. 沿用第 12/19 行的收益语义：`u_hat=+infinity` 仅为哨兵，新增根的 alternate payoff 为 `min(u_hat, u_tilde(h)) = u_tilde(h)`，对应 `B[empty, s_-(h)] = -u_tilde(h)`。进入求解器的收益必须有限；不能把哨兵当作实际收益输入 LP。R 非空时，新增根继续使用第 13/19 行从旧解得到的 u_hat 与该最小值规则。
4. 补样或重建完成后，重新绑定当前根信息集在新子博弈中的引用，并维护与 I'_new 的节点映射。D-02 的观测分组、B 中根行动序列、求解策略以及第 39 行行动采样必须使用同一份当前根信息集；不得残留指向旧树或空集合的引用。
5. 非终局且信息模型一致时，完整 I 应非空。若完整 I 为空，应报告观测/规则/信息集更新不一致并保留诊断记录，不能从真实裁判状态补入隐藏信息或用重复粒子掩盖问题。首次没有旧树/旧解时的初始化与状态保存流程继续在 D-04 中确认。

### 验证要求（待执行）

## D-05：深度追赶与支持集展开

- 状态：**本条方案已由用户于 2026-10-24 确认：保留 D.3 动态深度追赶门槛，父节点调度采用 Algorithm 15 第 32–38 行，并保留下述先选择后检查的边界及验证要求。多展开合法分支本身不构成结构性正确性错误，但资源开销与调度停滞风险仍须验证。当前仅完成决定记录，尚未实现或完成算法验证。**

### 原始依据与判断

### 第一处：已确认的动态深度门槛

令 z 为实际准备展开的非终局叶子，support 暂按数学上的正 realization weight 定义。MAYBE_EXPAND 除了拒绝已经展开的节点，还要求：

`(x(z) > 0 or y(z) > 0) and (depth(z) <= d or (x(z) > 0 and y(z) > 0))`。

- 深度从每个当前棋局候选根的 0 开始，按真实棋步的 ply 计数；人工 gadget 边不计入棋局深度。重新定位当前根后重新计算相对深度。每次我方决策的迭代轮次从 d=1 开始，每完成一轮展开尝试递增一次；同一轮内因模式转换再次求解不单独增加 d。
- 判断的是展开前 z 的深度；展开 z 会生成深度为 `depth(z)+1` 的子节点。门槛随迭代增大，不设置固定的最大搜索深度，也不要求所有浅层分支先完成展开。
- 超过门槛的例外必须在 z 上检查双方支持，不能因为其父节点 h 双方支持，就让所有子节点绕过门槛。双方均零的 z 始终不展开；仅一方支持且深度合格的 z 仍允许展开。
- 实际浮点 support 的容差与敏感性验证由 D-08 处理；本条不预先指定概率阈值。时间预算仍独立检查，深度门槛不能代替时间控制。

### 第二处：采用伪代码的父节点调度

在当前树完成求解后，使用这次有效策略及本轮开始时的树/前沿快照执行第 32–38 行。新生成的节点留到重新求解后的下一轮参与调度，避免查询尚未求解的新序列的 support。

1. 对至少有一个非终局叶子子节点的父节点 h，若 `x(h)>0 and y(h)>0`，遍历其所有子节点并尝试 MAYBE_EXPAND。已展开节点和真实终局跳过，其余节点再接受上述子节点自身的 support 与深度检查。
2. 否则，按第 36–38 行从 h 的非终局叶子子节点中选最有趣的一个，再调用 MAYBE_EXPAND。保留先选择、后检查的顺序；不静默改为只在已经通过门槛的候选中选择，也不自动改选第二名。

### 第二项：固定 epsilon 的依据、作用范围与当前证据

- 核对目标 arXiv v2 全文、官方 NeurIPS 正文与 supplement 后，未发现 Dark Chess 浮点零判定的 epsilon、容差或舍入规则。D.4 只描述 positive margins，Algorithm 15 第 24/28 行直接写 `<0` / `>=0`。文中 epsilon-NE 与 epsilon-uniform / bet / fold 的 epsilon 是其他参数，不是此处的零阈值。Gurobi 的默认参数不能当作作者未披露的模式判定实现。
- 固定范围为 `[-1e-15, +1e-15]`，两端均归零。因此模式判据等价于：`v_raw < -1e-15` 选 RESOLVE，否则选 MAXMARGIN。正负阈值用于保留三类诊断标签，零与正值在模式选择中同属 MAXMARGIN；不再因符号接近零而返回“未判定”或触发额外精度求解。
- 比较对象始终是当前 gadget 的完整 `x^T(A+B)y`。如果求解器内部为改善数值而整体缩放 LP，先恢复尺度再比较；Algorithm 12 的 B 缩放属于当前 gadget 定义，仍保留。主版本和 D-01 对照版本使用同一个固定 `1e-15`，不按当前局面、根数量或收益大小自动改变阈值。
- 本次校准使用原有 64 个 1×2/2×2 案例，但重新进行单次固定参数浮点求解：每例仅一次双方 LP 求解对，`highs-ds` feasibility tolerance 为 `1e-7`，不使用自动区间重试、精确概率修复或有理数策略重构。直接计算原尺度浮点收益，并以独立精确 oracle 仅作离线比较。此设置是校准环境，不据此冻结 D-08 的完整 LP 实现。
- 以“所选模式与精确 oracle 的负/非负判据不同”为主要误判指标。候选 `1e-8 / 1e-10 / 1e-12 / 1e-14 / 1e-15 / 1e-16` 分别产生 `17 / 13 / 8 / 6 / 4 / 5` 次模式误判；`1e-15` 在全部十个正候选中最少，所有精确零案例均归零。若并列，预设选择较大的 epsilon。本次两次完整执行 trace 相同。
- 4 次模式不符包括 2 个微小负值按零处理、2 个正值被浮点解误估成负值。精确正/零/负三分类共有 14 次不同，其中 12 个非零值被归零；不能把“4 次模式误判”说成所有符号都只有 4 次不同。这是同一小型校准集上的结果，不是实战错误率或完整规模误差保证。
- `configs/paper_2021.toml` 新增 `[mode_switch]`；`src/darkchess/numerics.py` 实现纯标量比较器，`tests/test_numerics.py` 覆盖闭区间、相邻浮点数与非有限值。详细依据、可重复命令及结果位于 `docs/d06_fixed_epsilon.md`、`configs/d06_fixed_epsilon_sweep.toml`、`scripts/sweep_d06_fixed_epsilon.py`、`results/d06_epsilon/fixed_sweep.json`。未接入尚未实现的 PaperAgent。
- 此前自动误差界、重试和未判定时保留模式的建议已被本次固定阈值决定替代；旧探针、结果和 `docs/d06_numerics.md` 保留为历史诊断资料，不是实时模式判断的必要步骤。NaN、infinity 或不合格的求解结果仍须报错/按 D-04 回退，不可借近零规则掩盖求解失败。

### 后续验证要求

- 标量比较器验证闭区间两端、紧邻阈值内外的浮点数、正负零、NaN/infinity；完整 gadget 后续测试正、负、精确零和阈值内外微小值。日志保留 `v_raw`、`v_decision`、是否归零、固定 epsilon、当前/下一模式、信息项贡献、求解设置和残差。

## D-07：Stockfish 13 的 FoW 适配缺失

### 原始证据与限制

- 固定提交 `3597f1942ec6f2cfbd50b905683739b0900ff5dd` 的 `position.cpp:523–550` 限制王的安全及 pinned piece；`evaluate.cpp:967` 的 classical evaluation 路径断言无 checkers。这说明需要兼容性核验，不能推导为整个引擎不能搜索普通棋中被将军的合法局面。
- `search.cpp:588–589` 在深度用尽后进入 quiescence search；原生 depth 1 不是直接调用一次静态评估。`ucioption.cpp:64,82–83` 默认 `Threads=1`、`Use NNUE=true`、使用默认网络；[官方 sf_13 evaluate.h](https://github.com/official-stockfish/Stockfish/blob/sf_13/src/evaluate.h) 指定网络名 `nn-62ef826d1a6d.nnue`。文件名不是完整 SHA-256 校验结果。
- [官方 sf_13 uci.cpp 的 UCI::value](https://github.com/official-stockfish/Stockfish/blob/sf_13/src/uci.cpp) 对同一分数通过互斥分支输出 `cp` 或 `mate`，不是同时输出两个可平均的分量；mate 距离单位是 moves，不是 plies。内部 `Value` 经过 `PawnValueEg` 换算才是 UCI cp，不能直接把内部整数除以 100 当 pawn units。

### 已确认：第 1–3 项及评估边界（2026-10-24）

1. 先以原版 Stockfish 13 为参考路线，完成 FoW 状态兼容性探针，再决定必要适配。外层规则、合法动作、观测和 KLSS 仍严格采用 FoW；普通棋搜索只提供候选完整局面的启发式叶值。不能让它裁定 FoW 合法性，也不能把“能输出分数”等同于“对 FoW 有正确语义”。
2. 使用原生 UCI `go depth 1`，保留 quiescence search 和该版本的搜索行为；不以 static evaluation 偷换 depth 1。外层 KLSS 的深度另行定义。
3. 保留 SF13 默认 `Use NNUE=true` 及原有 classical/NNUE 混合逻辑，锁定默认网络。获取引擎和网络后记录完整 SHA-256、构建选项、CPU 指令集和全部 UCI options；关闭 NNUE 只能作为显式对照版本。网络尚未在本项目获取和核验。
4. 有限 UCI cp 先换成固定求解方 ⊕ 的视角，再按 D-01 主版本使用 `tanh(cp_ours / 600)`。实际 FoW 终局优先，胜/和/负为 `+1/0/-1`，不能把缺王终局交给普通引擎。反过来，普通棋 checkmate/stalemate 不能直接宣告 FoW 终局。
5. 冻结完整配置；独立局面查询前重置引擎搜索状态。引擎缓存须包含按 D-09 规范化后的完整查询状态、引擎构建、网络、options 及 history 策略，不能仅按可见棋盘或遗漏易位/ep 权利的键缓存。缓存未 cap 的引擎分数；裁判终局结果不进入此省略历史的缓存，cap 按搜索路径另施加。输入只能来自 agent 的候选完整局面，不能取裁判真棋盘替代候选。

### 第 4 项：已确认的 mate 指数衰减、mate 0 特例与覆盖融合（2026-10-24）

- 用户改为保留所有非零 mate 距离的提示。令 `n` 为已换成固定求解方 ⊕ 视角的有符号 UCI mate 距离（单位为 moves），主版本统一使用 `u_mate(n) = sign(n) * 0.9 * 0.78 ** (abs(n) - 1)`，适用域为非零整数。负数用绝对距离衰减、负号表示我方劣势；当候选叶轮到对手走时，须翻转引擎分数符号，不能原样把其正 mate 当成我方正收益。
- 例：`n=±1 -> ±0.9`、`±2 -> ±0.702`、`±3 -> ±0.54756`、`±4 -> ±0.4270968`、`±5 -> ±0.333135504`。旧版 `|n|=2` 的 `0.7` 被精确的 `0.702` 替代，不为保留旧值而舍入。正、负 mate 共用同一个 `0.78` 衰减系数。
- 对所有有效 mate（包括下述 mate 0 特例），继续采用覆盖方案，不与 cp 平均，也不为了这一分支额外取得静态 cp 或子力差；映射结果已经是有界 utility，不再经过一次 `tanh`。有限 cp 分支仍按 D-01 的 `tanh(cp_ours/600)` 处理。真正 FoW 终局优先，主版本胜/和/负为 `+1/0/-1`。
- D-01 六倍收益对照采用 `6 * u_mate(n)`，例如 `|n|=1/2/3` 对应幅度 `5.4/4.212/3.28536`；终局为 `+6/0/-6`，两版本均保持 `M=10^7`。D-06 的 `epsilon=1e-15` 只作用于完整 gadget 值的模式比较，不对单个 mate 叶值提前截零。
- 数学上，有限非零距离的幅度在 `(0,0.9]`，距离增大时趋向 0；因此单独比较该启发值时偏好更近的正 mate、更远的负 mate。这是用户指定的工程偏好，不是已校准的 FoW 胜率或作者公开参数。普通棋 mate 仍不保证 FoW 中可吃王；该映射也不保证比其他行动的高 cp 估值更优。
- `mate 0` 的来源依据：归档 `sources/stockfish13/search.cpp:231–236` 在根无合法走法且被将军时给出 `-VALUE_MATE`，`sources/stockfish13/d07-material-2026-10-24/uci.cpp:292–301` 将其输出为 `mate 0`。在受支持的普通棋合法输入、未用 `searchmoves` 限制根动作的前提下，这表示候选局面的行动方已被普通棋将死；无走法但未被将军则是 draw 分支。论文 B.1 不以 checkmate 裁定 FoW 终局，故这里只能作为启发式叶值证据。
- 用户于 2026-10-24 确认 `mate 0` 特例：先排除真正 FoW 终局；在 FoW 非终局中，若普通棋被将死方是固定求解方 ⊕，取 `u=-0.9`，若是对手，取 `u=+0.9`。六倍对照分别为 `-5.4/+5.4`，与 `|n|=1` 共用幅度 0.9 的上限。保留被将死方身份（该候选局面的 `side_to_move`）以转换视角，不能靠整数 0 的符号或 `sign(0)` 判断；非零距离公式不适用于 0，也不能代入负一次幂。这是用户选择的工程映射，不是作者已公开的参数或 FoW 胜率。普通棋将死不改变该 FoW 节点的非终局性质、合法动作或后续可展开性。
- 引擎启动失败、超时、协议损坏、不受支持的输入、缺失或非有限分数仍是评估失败；不能把这些异常伪装成有效的 `mate 0`。此决定只解决有效 mate（含语义已确认的 0）的数值转换，不替代 SF13 对 FoW 状态的兼容性验证；失败仍按 D-04 处理。
- 状态：非零衰减、mate 0 特例、参数及覆盖融合均已获用户明确选择，并已写入规格配置；叶值后端与 agent 接入仍未实现。四个单线程引擎实例保持不变；LP 选择与验证状态见 D-08。

## D-08：LP backend 与支持集的数值近似

### 原始依据与歧义范围

### 已确认的六项处理（2026-10-24）

1. **合并什么状态。** agent 的 transposition key 使用完整候选棋子布局、行动方、双方易位权和按 FoW 合法性判断的有效 en-passant 权；不纳入真实 halfmove clock、重复次数及此前行动路径。不同隐藏棋子布局不能因我方当前视野相同就合并。裁判与精确小例 oracle 保留完整历史或等价的充分统计量，真实重复的 key 使用布局、行动方、易位权和有效 ep；重复次数与 100 ply 计数作为额外状态保存。agent 的和棋近似不改裁判规则、不读裁判私有计数器。
2. **同局面、不同对手知识保留谁。** 依 Algorithm 12，在当前 I 内对根分支按固定 seed 的独立随机流打乱，每个 key 保留第一个完整代表；将其对手信息历史及对应 alternate payoff/gift 一起保留，不将不同代表的 B 行混配，不取最乐观收益。记录代表选择以复跑；I 与 I' 的大小及均匀抽样按去重后的代表计，不因同一局面有更多历史路径而隐式增加权重。无合并且保留历史的版本只作小规模 oracle/消融。此合并是作者承认可能有偏差的近似，不是“同局面证明对手知道同样信息”。也不据此把整个 sequence-form 展开树合成无历史 DAG。
3. **何时标记 possible draw。** 只使用求解方自己的观测历史。按每个完成的 ply 更新一次，初始观测计一次；三次重复比较同一行动方阶段下的当前观测签名，含可见 mask、可见内容和已允许提供的规则/行动信息，不含请求 ID、绝对 ply 编号、真实隐藏棋子或整段历史。保留双方每次行动后立即更新观测的既有选择，重复 UI 刷新不累计次数。50 moves 按 B.1 前一句的 50 full moves 解为 100 ply；另维护自上次**可由本方动作或观测历史确认** pawn move/capture 后经过的 ply 数。看不见的对方 pawn move 不能仅因候选状态知道它发生而重置这个观测计数。相同视野不证明真棋盘重复，未看到事件不证明没发生；这些条件只触发启发式 cap，不裁和。
4. **cap 的数学对象和视角。** 先按 D-01/D-07 得到固定求解方视角的基础值 `base`：FoW 终局用规则收益且不调用 Stockfish，其他节点用转换后的引擎估值；再按第 5 项在触发路径上使用 `search_value = min(base, 0)`。例如非终局 `+0.7 -> 0`、`-0.4 -> -0.4`；不是统一置零或取绝对值。六倍对照同样以 0 为上限。有效 mate（含 mate 0）也适用。cap 仅作用于搜索中的局面收益，不对完整 A+B、alternate payoff、gift 或 D-02 信息项作统一截断；依赖局面收益的后续计算自然使用已 cap 的数值。对手在同一个零和子博弈中的收益为该固定我方收益的相反数，不再独立对两方收益各 cap 一次。
5. **后继、缓存及终局处理——按原文字面覆盖所有后继。** 触发后，后续 pawn move/capture 可重置观测静默计数，但不清除该路径已有的 cap 标记；复用搜索树及重定根时保留已有标记，新棋局清除。相同局面在不同观测路径的 cap 状态可不同，缓存原始引擎估值后按路径施加 cap，不能用共享局面缓存传播已 cap 的结果。用户选择不保留终局例外：搜索中触发节点及所有后继（包括真正终局）的收益都以 0 为上限，因此主版本胜/和/负基础值 `+1/0/-1` 在 cap 路径变成 `0/0/-1`，六倍版本 `+6/0/-6` 变成 `0/0/-6`；未触发的路径仍使用原值。终局节点依然是终局，不继续展开，也不调用缺王 Stockfish 查询。真实裁判结果、对外终局通知和实验 W/D/L 不受此搜索近似影响，实际获胜仍记胜。这是用户对 B.1 “all its descendants”的明确字面选择；缺少作者代码，不能宣称已经验证作者如何编码终局。之前提出的终局例外作为未采用建议废止。

## D-12：Algorithm 12 的 gift 求和下标及符号一致性

- 状态：**2026-10-24 完成相关原文的目视核对；用户于 2026-10-25 确认采用下述统一约定，明确采用非负 gift 并加到 B。决定已写入规格配置，完整计算及运行时边界尚未实现验证。** 原条目只记录下标疑点；与其直接相关的减项、min/max 和 B 符号一并处理，不能只修一个字符便认为 reach 已正确。作者实际实现仍未知。

### 原始证据与判断依据

- P1 第 19 页 Algorithm 12 第 23 行和 P3 物理第 7 页（印刷页码 19）均实际印为 `I'a' ≺ I'`，不是 PDF 文本抽取错误。本文的祖先/前缀关系及 perfect recall 语义下，执行动作后的序列不可能是其来源信息集的严格前缀；照字面筛选会得到空和，令该项 gift 恒为 0。这里求和变量 `I'` 是对手信息集，不是 Algorithm 15 中搜索根集合 I'。
- 算法左侧是 `g_hat(I0)`，外围第 9 行逐个处理对手根信息集 I0，因此推断求和终点应为这个 I0。为避免变量重名，建议改写成对手祖先信息集 J 与动作 a，条件为 `Ja ≺ I0`，通过对手序列/历史的前缀关系判断。
- P1 第 17 页 D.4 脚注 2 实际写 `sum_{I'a' ≺ I}(u*(x|I'a') - u*(x|I))`，第二项是无撇的 I；第 23 行却减 `u*(x|I')`。gift 衡量同一个对手决策点上，通向目标根的行动相对于当时最佳行动的损失，因此建议采用局部比较 `V_x(Ja) - V_x(J)`，而不是让所有过去行动都减当前根的值。脚注对 gift 只是估计、不是可靠下界的明确说明仍保留。
- P1 第 3 页 §2 的定义用我方收益 u 并对对手策略 y 取 min，随后却印 `u*(x|I) = max_a u*(x|Ia)`。在固定我方收益视角、对手行动的信息集上，最佳响应应选择 min；这两处字面写法不相容。建议实现时使用显式的我方视角值 V_x，避免同一 u* 混用双方收益。
- P1 第 19 页第 21 行写入 `-u*(x|I0)`，第 22 行再减 gift。若采用前述我方视角与非负 gift，这会缩小而非扩大 margin。其直接引用的 Brown–Sandholm 2017《Safe and Nested Subgame Solving for Imperfect-Information Games》§5、第 7 页公式 (1) 明确为普通 margin 加上非负 gift。该文使用对手收益的 CBV 约定，换到我方收益时须同时翻转收益视角，不能只照搬 max 或差分顺序。
- 引用文献归档于 `sources/references/d12-reach-2026-10-24/`，独立 manifest 保存 URL、时间和 SHA-256；原来源清单未重写。新增核对页保存在 `results/d12/source_views/`，D.4 页复用既有 `sources/paper/renders/arxiv-17.png`。

### 已确认的统一约定（2026-10-25）

1. **路径范围：** 对 Algorithm 12 当前处理的每个 I0，累计旧输入博弈 Gamma 中满足 `Ja ≺ I0` 的对手祖先决策。每个 I0 用其对应的候选对手历史，不从裁判真实隐藏动作日志取路径，也不把其他根的路径混入；无符合条件的祖先时取空和 0。
2. **值与局部差分：** 固定旧树/旧策略及我方收益视角，用 `V_x(J) = min_a V_x(Ja)`；单步 gift 为 `G(J,a) = V_x(Ja) - V_x(J)`，在同一个精确模型内非负。所有数值来自同一旧 blueprint 的 counterfactual best-response 计算，不能使用相邻两次 Stockfish 估值差，也不能混用新旧树。此处的非负性不意味着近似 Dark Chess 模型给出了真实游戏中的安全下界。
3. **写入 B：** 定义 `G_hat(I0) = sum_{Ja ≺ I0} G(J,a)`，代码保存非负 gift，第 21–22 行的局部初始化采用 `B[empty, s_opponent(I0)] = -V_x(I0) + G_hat(I0)`。之后第 24–27 行的旧 B 复制、缩放和遗漏分支贡献仍继续执行。带符号的 `g_hat = -G_hat`、`B -= g_hat` 只作为等价表示的交叉校验，不作为另一套默认配置；不能同时使用非负 G 与减 G。D-06 的完整 A+B 比较与模式转换缩放保持不变，各 value 版本按自身收益重新计算 gift。
4. **不足与重复计入：** 按下述一致性原则处理新根缺失、重建、初始化和复用；具体不可计算分支仍须随阶段 3 小树实现明确并验证，不能宣称上述公式已覆盖完整运行路径。

   - 新增根不在旧树中时，按 D-03 使用 `alt(h) = min(u_hat, u_tilde(h))`、`B[empty, s_opponent(h)] = -alt(h)` 初始化，不附加无法由旧树计算的历史 gift。旧根全失时显式重建并更新根引用；`u_hat=+infinity` 只作哨兵，实际 alternate payoff 为有限的 `u_tilde(h)`。这表示此次没有可用的历史 gift 估计，不断言对手过去没有失误。
   - 每次构建绑定旧树/旧策略快照与目标根，记录祖先差分、counterfactual value 的收益组成及旧 B 来源。相同输入重复构建不得累加一份已经计算过的完整路径 gift；旧模型改变时允许从该模型重新计算，不能用“一个真实动作终生只计一次”的全局去重规则代替。
   - 按算法复制旧 B 本身不是重复计入。反事实值中的收益项与 B 的复制、保留质量归一化、模式转换必须使用一致的约定；不能一边漏算旧 B 对旧值的贡献，一边保留旧 B，也不能为避免重复而直接删除第 24–27 行。
   - 显式检测零 counterfactual reach、零归一化分母和非有限值。对手旧策略给某动作概率 0，并不单独意味着该处 counterfactual reach 为 0。不得用分母加 epsilon、NaN 转 gift 0 或无依据截断掩盖未定义值；也不套用 D-06 的模式比较 epsilon 作为 gift 裁剪阈值。新根初始化与不可计算的可复用旧分支须区分；在后者的合法处理路径完成验证之前，不接受含未定义值的解，失败按 D-04 使用当前决策的有效快照或显式报错。具体数值分支的最终实现仍待阶段 3 确定。
