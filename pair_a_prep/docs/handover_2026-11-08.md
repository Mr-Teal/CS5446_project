## 1. Summary

- **Reported score vs the greedy bot.** With a 5 s search allowance, the author reports scores against the greedy
  Material OnePlyBot 0.919-0.924 with the material leaf and 1.000 with a Stockfish 14.1 depth-1 leaf.
- **Reported trained leaf.** A belief network trained on 19,749 solver records is reported at
  87-0-3 (0.967) against the same bot. On the 66 seeds both leaves finished, it does better on 5 and
  worse on 1 (sign test p = 0.22): **neither improvement nor equivalence is established.**
- **Reported offline validation error is higher for the network than for the material formula.** Board MAE is 0.091, against 0.059 for
  material counting.
- **Reported one-pass pipeline.** The author reports one labels -> network -> leaf cycle.
  The next step (new labels from the network-leaf agent, retrain, repeat) has not been run.
- **Memory is a reported resource limit.** Exact belief tracking costs more memory than the papers' setting at
  256 roots and on long games. The 256-root arm completed only 17 of 50 chunks at 15 GB on Atlas.

### 4.3 Solver labels and the trained network (Pair B review scope)

Labels: the fe-s16-style agent in self-play (material leaf, 5 s, 16 roots, 96k tail guard), per-hypothesis
values in [-1, 1], root value, root and played policy.

| Source | Reported game/part count | Records | Author-reported format validation |
|---|---|---|---|
| Atlas, 10 tasks x 24 (NUSREC-HPC-00001) | 240 (5 failed) | 14,073 | 0 errors |
| Homelab | 96 of 120 (stopped) | 5,676 | 0 errors |
| Merged `solver-v1` | 336 (train 268 / val 34 / test 34) | 19,749 | 0 errors, one config_id |

The counts sum to 19,749 records and 336 reported game IDs/parts; they do not establish 336 finished
self-play games. The inspected label runner writes partial records even when a game fails, and later
resumes skip an existing part. The archive needs to show which failed/partial parts were retained, unique
game IDs across both hosts, and the actual train/validation/test membership. One `config_id` does not
establish identical trajectories across platforms or validate the target semantics.

"0 errors" refers to the author's validator run. The available validator checks schema, value ranges,
weighted-root consistency, encoding and optional split membership. It does not certify solver correctness,
history-sensitive continuation values, representative sampling, or exact support after pruning. PR67's
known defects therefore remain relevant even when record-format validation passes.

Network `belief-solver-v1` (Pair B `train_belief_net.py`): 6 residual blocks x 64 channels, 128-dim
embedding, 32 input planes, belief context on, 561,681 parameters; AdamW lr 0.002, weight decay 1e-4,
cosine schedule; batch 64 beliefs / 4,096 boards; best epoch 7 of 12 (patience 5). Latency on the RTX 5070 Ti:
0.49 ms per 8-board belief at batch 1, 0.022 ms at batch 64.

Author-reported validation split (34 games, 2,196 beliefs; metrics not independently recomputed):

| Predictor | Board MAE | Position MAE |
|---|---|---|
| Material `tanh(cp/600)` | 0.059 | 0.059 |
| Network, no context | 0.088 | 0.080 |
| Network | 0.091 | 0.084 |
| Constant 0 | 0.589 | 0.584 |

A possible explanation for the higher reported network error is that the two-ply labels are derived from
material-valued leaves. This is a hypothesis, not an isolated causal result. The author reports the test
split remains unused; the missing split/training artifacts prevent independently confirming that claim.

Training with `use_context=True` is supported by the architecture, but the inspected deployed search calls
`evaluate_children(fen)`. `BeliefNetworkEvaluator` turns each child board into a singleton belief for that
call; it does not pass the player's full live belief to the network. These reported game arms therefore do
not validate whole-belief online learning or the strategic value of information. The new model is separate
from archived Network 1 and the completed seven-row evaluator batch.

## 5. Failure modes worth knowing

- **Dead belief.** The tail guard prunes uniformly before an update; if the true history is pruned, a later
  observation matches nothing (`BeliefBudgetError: no_candidate`). About 1 game in 60 in arms; there is no
  recovery (Obscuro tops up to 256 roots).
- **Memory kills.** One belief update can grow the state set 4-23x, so any cap can be crossed mid-update:
  docker exit 137, PBS Exit_status 9. Resuming/retrying requires checking the persisted outputs and stopping policy; neither approach guarantees completion or bounds peak memory.
- **Orphan containers.** `run_arms4.sh`'s `timeout` kills the docker client, not the container. Orphans froze
  the VM twice (Nov 3-4, Nov 4-5). Check `docker ps` for `fow-*` containers older than 30 min.
- **Greedy bot's tracker.** Two network-arm games ended with the opponent's `TrackerLost`; not our agent.
