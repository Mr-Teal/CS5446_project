# Toy knowledge restriction and interactive inspection

Implementation: [knowledge.py](../knowledge.py). The source for the knowledge
radius and freezing distinction is [Obscuro, Appendix B.2 and C.6](https://arxiv.org/pdf/2506.01242v2).
This implements a finite **synchronized cut**, with both players' observations
explicitly provided at every candidate root. It does not discover knowledge
from FENs, infer private histories, or construct a full chess KLUSS graph.

## Construction

`CutRoot` records root identity, both observation IDs, a continuation tree and
externally supplied reach mass. Equal own observation IDs define I^1 for the
chosen observation. Edges connect roots sharing either player's observation.
I^2 retains distances 0 and 1, followed by their continuation subtrees. More
distant roots and disconnected components are removed. Both players' cut
partitions are required, including nonacting observations; future decision-node
keys alone cannot supply the missing observation data.

The KLSS control replaces retained player-0 information sets not touching an
I^1 continuation by chance nodes using the blueprint's fixed distribution.
KLUSS keeps those same roots but leaves their own strategies optimizable. It
does not split existing information sets by simulator root identity.

The result connects directly to `build_gadget` and `PCFRPlus`. Blueprint data
is mandatory for frozen information sets. Input trees are copied, inconsistent
action definitions are rejected, and the gadget's perfect-recall checks still
apply. The caller must supply semantically valid observation partitions and
continuation infosets; shape validation cannot prove their information meaning.

## Demonstration and expected results

```python
from pair_a_prep.knowledge import knowledge_demo, restrict_cut
from pair_a_prep.pcfr import PCFRPlus

roots, blueprint = knowledge_demo()
cut = restrict_cut(roots, "current", blueprint, mode="kluss")
gadget = cut.gadget({"J0": 2.0}, mode="resolve")
solver = PCFRPlus(gadget.tree, schedule="alternating")
solver.run(200)
print(cut.distances, cut.retained, cut.frozen)
print(solver.metrics())
```

The constructed chain is A--B--C--D with disconnected E. A is current; B
shares the opponent's observation, C shares B's own observation, D shares C's
opponent observation. Only A and B remain. A is matching pennies, while B has
a bad/good decision with payoffs -1/+1 and a bad-only blueprint. The Resolve
alternate payoff +2 ensures the minimizing opponent prefers entering here.
The LP values are -.5 for frozen KLSS and +.5 for KLUSS. The improvement is
for this constructed subgame; it is not a full-game safety or strength claim.
The deliberate removed payoffs +/-10 help catch accidental root inclusion.

## Browser visualization

Open [the generated explorer](../results/toy_explorer.html) directly in a
browser. It is a self-contained HTML file, with no server, CDN or internet
connection required. All displayed checkpoints are generated by the Python
solver; the browser replays them rather than implementing a second solver.

- Select matching pennies, hidden coin, Kuhn poker, either knowledge mode,
  or a Maxmargin gadget.
- Play/pause, step, or scrub recorded solver rounds.
- Switch between last and average strategies.
- Click a tree node to highlight its shared information set; inspect edge
  action probabilities, continuation values and projected regrets.
- Compare both Nash-gap curves and the LP reference value.
- In knowledge scenarios, inspect root distances, retained/removed roots and
  frozen own information sets. The frozen policy appears as a chance node.

This is an omniscient debugging view, never a player observation. Gaps and LP
values refer to the displayed restricted/gadget game, not the full original
game. Later checkpoints can skip rounds and are labeled with their real round.

Regenerate a fresh artifact without overwriting previous output:

```powershell
python -m pair_a_prep.toy_visualizer --rounds 200 --output pair_a_prep/results/toy_explorer_new.html
python -m pytest -q tests pair_a_prep/tests
```

Remaining work includes a general history/observation representation, real
KLUSS root construction from tracker histories, blueprint reach and gift
updates, one-sided tree growth and persistence. This finite-cut demonstration
does not claim to complete those parts of Obscuro.
