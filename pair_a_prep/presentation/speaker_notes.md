## Slide 4: Hidden State Stays Behind the Referee (75 seconds)

**Purpose:** explain the input boundary and state representation, connecting
the preceding information-set example to the actual chess implementation.

**Suggested script (~125 words):**

The referee owns the true board and applies the rules. The player receives
only its private observation: visible pieces, legal moves on its turn, and
the information in its observation history. The tracker retains candidate
histories consistent with that evidence. Here White played Ka1-b1; Black
could then have played Kh8-g8 or Kh8-g7. Both complete histories give White
the same private evidence and legal-move feedback. White therefore needs one
policy that can be executed without knowing which candidate is real. The
full candidate boards are hypothetical search inputs, not a leak of the
referee's true board. History also matters: a FEN alone does not retain
repetition or private memory. Our exact-history tracker is distinct from
the bounded particle configuration used in Pair B's evaluator matches.

**Point to:** the left shaded board first, then A/B. Do not label either A/B
as the true board or claim these two candidates exhaust the belief. Their
illustrative equal weights are not a calibrated opponent-policy posterior.

**Transition:** “Once we have a consistent set of hypothetical histories,
how do we allocate search without restarting all the work?”

**Backup answers:**

- Observation: visible squares/pieces, own legal moves, ply/side-to-move,
  capture notices and terminal feedback; it is not a full board.
- Belief: weighted consistent hypothetical histories. An information set groups
  indistinguishable histories; belief weights are a separate concept.
- Evaluator: may score hypothetical full boards generated by the tracker.
  It is not allowed to receive the referee's actual hidden board as a fact.
- Identical FENs can retain different histories, repetition stacks and private
  memories; the displayed A/B example instead uses different FENs with the
  same White evidence. These are complementary points, not the same example.

## Slide 5: Grow Search Without Restarting Its Learning (75 seconds)

**Purpose:** explain what the implemented growth contract does, how it fails
safely, and how it differs from the original paper.

**Suggested script (~130 words):**

Our search starts with a shallow information-set tree. The yellow leaves are
estimated nonterminal frontiers, not real game endings. We prepare new
continuations, evaluate their children and validate the result before changing
the active tree. Old regret minimizers and their accumulated state survive;
only newly introduced information sets receive new solver state. In this
example one of three frontiers grows, leaving two untouched. The exploring side
alternates after each successful expansion. It uses a half support-uniform,
half variance-PUCT mixture; the other side follows its raw CFR policy. The agent alternates
solving and growth, then reserves work for final solving. If a growth attempt
does not fit, it retains the old tree. If even initial preparation cannot
finish, it can still return a legal action, but does not fabricate a training
label. These checks support implementation behavior, not stronger play. Our
displayed fixture grows within one turn. The integrated prototype also retains
raw blueprints across turns and projects boundaries inside the saved sampled
tree. Complete history-space KLUSS and gift bookkeeping remain unfinished.
Deadlines remain cooperative.

**Point to:** the blue White node retained in both panels, then the new green
Black node and yellow estimates. If another hidden occurrence of the same Black
information set is expanded later, it shares the existing policy. The root
chance node is omitted for legibility.

**20-second evidence callout:** the fixture expands from 3 to 5 frontiers;
old minimizer identity, regrets, averages and the completed round count
remain unchanged during the graft. Counts and evidence are in `evidence.json`.

**Backup answers:**

- Original paper: explore with one player at a time, alternate after each
  expansion, select a leaf using a half support-uniform / half PUCT policy.
  The other player keeps its current strategy. See the audit for exact formula.
- This implementation: optional one-sided growth, serial stages, best-child
  initialization for initial and growth infosets in selective modes,
  opt-in cross-turn raw blueprints and sampled-tree gadgets, no complete
  Obscuro claim. The shown picture is the small within-turn graft fixture.
- One-sided exploration is different from alternating PCFR+ updates. Keeping
  those concepts separate is essential when explaining the current code.
- The budgeted agent follows the raw sampled-root path. The gadget growth API
  exists separately; paper-derived alternate/gift/prior inputs remain missing.
- Growth can use more evaluator calls than direct deeper construction. Failed
  preparation consumes actual work even when the committed tree is unchanged.
- Engineering comparison: the three-seed kings-only Material root fixture used
  68 nodes / 13 calls with uniform growth and 22-24 nodes / 5 calls with selective
  growth. Both use 12 CFR rounds and equal upper limits, not equal actual work.
  The two six-ply matches are capped with null outcomes: no strength claim.
  Full records and timings: `../results/one_sided_reference.json`.

## Slide 5 backup: Clock budgets and purification (45 seconds)

The table reports four caller-timed samples per condition, with cold standard
positions and a separately prepared saved-blueprint fixture. Purification has
matched fixed-work controls: the raw strategy and labels stay unchanged, while
the output distribution can change. With wall-clock stopping, actual solver
work may differ between runs, so this is not an isolated strength comparison.

The first matrix with no submission reserve had 16 overruns in 48 single-turn
checks. A 10% finalization reserve and previous-round estimate gave zero in the
matching reserved matrix. This is an observed small-sample result, not a hard
deadline guarantee: an executing CFR round or evaluator call cannot be stopped.
The 20 ms cold turns all fell back, so their low latency is not completed search.

Both live matrices used 12 four-ply pawn games, all capped with null outcomes.
The reserved run had no overruns but still 11 fallbacks. Report fallback work and
reasons honestly. Source JSON, configuration and caveats are in
`../docs/clock_purification_ablation.md`; the SVG table is generated from them.

## Historical clock evidence clarification

Every non-fallback raw policy in the archived matrix was an exact tie; purification measures move-order tie-breaking. Only 16/48 standalone turns exercised the guard (24 hit the round cap; 8 fell back). The reserved live run had 11/48 fallbacks.
