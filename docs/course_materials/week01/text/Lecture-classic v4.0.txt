Classical Planning                                                                                  10
Main Characteristics
• PDDL:
     • Standard language for planning, derived from STRIPS; many extensions
• Logic-based representation:
     • Compact, lifted form of propositional logic (restricted FOL)
• Factored state representation:
     • World described as state variables or fluents
     • Fluents = properties that change over time
• Implicit transitions:
     • Actions define how states change
     • Other states generated as needed
• Domain-independent heuristics:
     • General methods to guide search across different domains

State Representation
• State
     • A state is a conjunction of ground atomic fluents or a set of fluents that are true.
     • Ground atomic: a predicate with only constant arguments; function-free.
     • Examples:

The Frame Problem
• Challenge:
     • Specify what changes after an action without restating everything unchanged.
• In PDDL:
     • Closed-world assumption: unmentioned facts are false
     • Fluents have no explicit time reference
     • Preconditions hold at time 𝑡; effects apply at time 𝑡 + 1
• Key idea:
     • Only list changes; all other facts are assumed unchanged.

Example: Planning Domain in PDDL
(define (domain air-cargo)
  (:requirements :strips :typing)
  (:types plane airport cargo)
  (:predicates
    (At ?x - (either plane cargo) ?a - airport)
    (In ?c - cargo ?p - plane)
    (Cargo ?c - cargo)
    (Plane ?p - plane)
    (Airport ?a - airport))
 (:action Load
    :parameters (?c - cargo ?p - plane ?a - airport)
    :precondition (and (At ?c ?a) (At ?p ?a) (Cargo ?c) (Plane ?p) (Airport ?a))
    :effect (and (not (At ?c ?a)) (In ?c ?p)))
  (:action Unload
    :parameters (?c - cargo ?p - plane ?a - airport)
    :precondition (and (In ?c ?p) (At ?p ?a) (Cargo ?c) (Plane ?p) (Airport ?a))
    :effect (and (At ?c ?a) (not (In ?c ?p))))
  (:action Fly
    :parameters (?p - plane ?from - airport ?to - airport)
    :precondition (and (At ?p ?from) (Plane ?p) (Airport ?from) (Airport ?to))
    :effect (and (not (At ?p ?from)) (At ?p ?to))))

Planning by Forward Search
• From Start → Goal using Actions
• Begin at Initial State
     • If 𝑆𝑡𝑎𝑡𝑒 ⊨ 𝐺𝑜𝑎𝑙 (or 𝐺𝑜𝑎𝑙 ⊆ 𝑆𝑡𝑎𝑡𝑒), you’re done.
• Find Applicable Actions
     • Action is applicable if 𝑆𝑡𝑎𝑡𝑒 ⊨ 𝑃𝑟𝑒𝑐𝑜𝑛𝑑(𝑎) (or 𝑃𝑟𝑒𝑐𝑜𝑛𝑑(𝑎) ⊆ 𝑆𝑡𝑎𝑡𝑒).
• Generate Successor States
     • Apply effects:
     • 𝑠′ = (𝑠 − 𝐷𝐸𝐿(𝑎)) ∪ 𝐴𝐷𝐷(𝑎)
• Move Forward
     • Pick a successor as the new current state.
• Key Idea:
     • March forward by adding what actions give and removing what they take away.

Planning by Backward Search
• From Goal ← Start by Regressing Goals
• Begin at Goal Description
     • If 𝐺𝑜𝑎𝑙 ⊨ 𝐼𝑛𝑖𝑡𝑖𝑎𝑙 𝑆𝑡𝑎𝑡𝑒 (or 𝐼𝑛𝑖𝑡𝑖𝑎𝑙 𝑆𝑡𝑎𝑡𝑒 ⊆ 𝐺𝑜𝑎𝑙), you’re done.
• Find Relevant Actions
     • At least one effect matches the goal.
     • No effect contradicts the goal.

SATPlan Summary
• Frame Problem:
     • Most actions do not change most fluents.
     • For 𝑚 actions and 𝑛 fluents:
     • Naive: one axiom per fluent unaffected by each action → 𝑂(𝑚𝑛) axioms.
     • Successor-State Axioms:
     • A clever encoding that handles the frame problem well.
     • Encode only actions affecting a fluent → 𝑂(𝑛) axioms (longer but fewer)
• SATPlan
     • Finds reachable action sequences; returns shortest plan if exists.
     • Works in fully observable or sensorless settings.
     • Limits: may include impossible actions; high memory usage.

Characteristics of Planning
• Algorithm Properties
     • Soundness: All generated plans are valid solutions.
     • Completeness: If a solution exists, it will be found.
     • Optimality: Best plan found if admissible heuristics are used.
• Complexity
     • PlanSAT: Is there any solution?
     • Bounded PlanSAT: Is there a solution of length ≤ 𝑘?
     • Both decidable (finite states); in general, in PSPACE.
     • Bounded PlanSAT often NP-complete; PlanSAT is in P.
     • Optimal planning is hard; sub-optimal planning often easier.
     • In practice: effective heuristics and alternative planning models help
