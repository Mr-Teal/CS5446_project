Problem 1 — Blocks World

PDDL domain

 (define (domain middle-pop)
   (:requirements :strips :typing :negative-preconditions)

     (:types
       thing
       block - thing)

     (:constants
       table - thing)

     (:predicates
       (on ?x - block ?y - thing)
       (clear ?x - thing))

     (:action move-to-block
       :parameters (?x - block ?from - thing ?to - block)
       :precondition (and (on ?x ?from) (clear ?x) (clear ?to))
       :effect (and (not (on ?x ?from)) (on ?x ?to)
                    (clear ?from) (not (clear ?to))))

     (:action move-to-table
       :parameters (?x - block ?from - block)
       :precondition (and (on ?x ?from) (clear ?x))
       :effect (and (not (on ?x ?from)) (on ?x table) (clear ?from)))
 )


PDDL problem

 (define (problem middle-pop-instance)
   (:domain middle-pop)

     (:objects
       a b c - block)

     (:init
       (on a b) (on b c) (on c table)
       (clear a) (clear table))

     (:goal
       (and (on a c) (on b table) (on c table)))
 )

Problem 2 — Delete-Relaxation Heuristic
Removing all delete effects is a relaxation: facts only accumulate, so every plan of the original
problem is still valid, and the relaxed optimal cost is a lower bound on the true optimal cost
(admissible when solved optimally).
This fails with negative preconditions or goals. Counterexample:

 Initial state: p
 Action remove-p:                 precondition: p                effect: not p
 Goal: not p

 Original: solved by remove-p.
 Delete-relaxed: the effect "not p" is removed, so p stays true
                 and "not p" can never be achieved -> unsolvable.
