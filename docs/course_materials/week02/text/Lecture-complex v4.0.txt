(define (domain air-cargo)
  (:requirements :strips :typing)
  (:types plane airport cargo)
  (:predicates
    (At ?x - (either plane cargo) ?a - airport)
    (In ?c - cargo ?p - plane)
    (Cargo ?c - cargo)
    (Plane ?p - plane)
    (Airport ?a - airport))
 (:action Load
    :parameters (?c - cargo ?p - plane ?a - airport)
    :precondition (and (At ?c ?a) (At ?p ?a) (Cargo ?c) (Plane ?p) (Airport ?a))
    :effect (and (not (At ?c ?a)) (In ?c ?p)))
  (:action Unload
    :parameters (?c - cargo ?p - plane ?a - airport)
    :precondition (and (In ?c ?p) (At ?p ?a) (Cargo ?c) (Plane ?p) (Airport ?a))
    :effect (and (At ?c ?a) (not (In ?c ?p))))
  (:action Fly
    :parameters (?p - plane ?from - airport ?to - airport)
    :precondition (and (At ?p ?from) (Plane ?p) (Airport ?from) (Airport ?to))
    :effect (and (not (At ?p ?from)) (At ?p ?to))))

Notes: ℎ!! : The Fast Forward Heuristic
• How it works (Hoffmann & Nebel, 2001)
     • Ignore delete effects → build a relaxed problem where facts never become false.
     • Compute relaxed plan → greedily select actions to achieve remaining goals.
     • Heuristic value → ℎ99 𝑠 = number of actions in this relaxed plan.
• Key properties
     • Highly informed → more accurate than simpler heuristics like ℎ:;< .
     • Inadmissible → may overestimate cost because greedy extraction can give longer-than-
       optimal relaxed plans.
     • Effective in practice → widely used in satisficing planning (e.g. greedy best-first search).

• State Abstraction
     • Group states into abstract ones → smaller search space

Real World Planning and Acting                                 30
Hierarchical Task Networks (HTNs)
• Hierarchical decomposition planning
     • Built on High-Level Actions (HLAs)
     • Assumptions: full observability, determinism, primitive actions with
       preconditions/effects
     • Applications: planning, problem-solving, decision-making
• High-Level Actions (HLAs)
     • Refinable into sub-HLAs or primitive actions (recursive)
     • Encode procedural knowledge, support multi-level planning
     • HLA achieves a goal if at least one refinement succeeds (agent chooses)
     • Different from nondeterminism: choice is deliberate, not uncertain
     • Example: Go(Home, SIN) → Drive / Taxi / MRT → primitive steps

Real World Planning and Acting                                                   31
HTN Planning
• Main idea
     • Start with top-level task/action, refine until primitive actions only
• Algorithm
     • Select an HLA in the current plan
     • Replace with one refinement
     • Repeat until plan is primitive and satisfies goal
• Search strategies
     • Breadth-first (by refinement depth)
     • Depth-first, iterative deepening
     • Graph search

Task Decomposition & Subgoal Planning
• Goal
     • Combine LLM commonsense reasoning with symbolic planners for complex tasks.
• Approach
     • LLM decomposes high-level goals into subgoals.
     • Subgoals encoded in PDDL and solved by planners.
     • Complex subgoals handled by Monte Carlo Tree Search (MCTS) with LLM policy.
• Example
     • Kwon et al., ICRA 2025 ArXiv | Github
     • Hybrid symbolic + MCTS planning reduces time and boosts scalability (reduces planning
       time while maintaining competitive success rates vs. baseline).
     • Planner: PDDL-based symbolic planner (Fast Downward as baseline) + MCTS-based LLM
       planner for complex subgoals.

Generalized Planning in PDDL Domains with LLMs
• Goal
     • Leverage LLMs as generalized planners to learn reusable strategies across PDDL domains.
• Approach
     • LLM (GPT-4) prompted with PDDL domain descriptions and two training tasks.
     • LLM + Chain-of-Thought extracts domain rules and strategies.
     • LLM generates domain-specific Python programs for new tasks.
     • Automated debugging refines outputs via re-prompting.
• Example
     • Silver et al., AAAI 2024 AAAI
     • No classical planner used — LLM generated programs directly, compared against classical baselines.
     • LLM (GPT-4) generalized across 7 PDDL domains with only 2 training tasks; often rivaling or
       surpassing classical baselines when automated debugging was applied.

From Classical to Modern Planning: Next Steps
• Classical planning remains highly relevant
     • Crucial in robotics, logistics, space mission planning, game AI, and multi-agent coordination, etc.
• • Scaled via:
     • Heuristics from relaxed models and abstractions
     • Hierarchical decomposition (HTNs, HLAs)
     • Emerging LLM-assisted methods for PDDL model generation, subgoal planning, and heuristic learning
• Yet real world environments involve uncertainty
     • Noisy sensors, incomplete information, and stochastic dynamics
     • Goals often involve trade-offs among preferences, risk, and utility
