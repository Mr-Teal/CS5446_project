Programming
Welcome to the Elevator Challenge! This assignment will immerse you in a classic AI planning
problem set in the bustling environment of a high-rise building during the evening rush hour. Your
mission, should you choose to accept it, is to design and implement planning solutions for a single
elevator serving passengers with different start and destination floors. This seemingly simple sce-
nario brings a host of planning challenges involving state modelling, capacity constraints, ordering,
and service quality.

Background: The Elevator Domain
The Elevator Domain is a well-known problem in AI planning that captures the intricacies of
coordinating movements in a constrained environment. Imagine a busy office building with several
floors and passengers travelling between different parts of the building. There is ONLY ONE
elevator, but its capacity is specified by each problem configuration. The elevator can start from
any floor and may need to make several trips to serve all passengers while respecting its door and
occupancy constraints.
    For more insight into the elevator’s operation, please explore the provided interactive Jupyter
notebook, 0 env walkthrough.ipynb, where you can play around with different scenarios
and understand the domain constraints and dynamics in detail.

About the Unified Planning Library
This assignment is part of a broader exploration of AI planning techniques, leveraging tools from
the AIPlan4EU project, a European initiative aimed at advancing AI planning technologies. AI-
Plan4EU provides a Unified Planning Library designed to offer flexible and powerful planning
solutions, integrating different planning paradigms, such as classical PDDL (Planning Domain
Definition Language) and Hierarchical Task Network (HTN) planning.

problem effectively.

Problem 1: Classical Planning (2 points)
In the first task, you will implement a solution using the Planning Domain Definition Language
(PDDL), a standard language for expressing planning problems. You will first model passenger
requests with arbitrary start and goal floors, then extend the model with destinations, completed
trips, and a configurable elevator capacity. The model and problem generators should work for
every valid configuration described in the notebook.
    Instructions: Complete this part in the 1 PDDL.ipynb Jupyter notebook, following the de-
tailed guidelines provided. After completion, copy the required blocks to 1 PDDL solution.py.
There are four parts to the problem: foundational domain, foundational problem generator, capacity-
aware domain, and capacity-aware problem generator. Only the two capacity-aware tasks are
graded (1 point each, 2 points total). The foundational tasks are ungraded. AI assistance is per-
mitted and encouraged, but you are responsible for checking that the resulting model captures the
intended rules. The solution script includes an optional space for concise AI-audit notes; it is not
read by the autograder, and carries no marks. Prompt transcripts and AI usage records are not
graded.

Problem 2: Hierarchical Planning (8 points)
Hierarchical Task Network (HTN) planning is a method that breaks down complex tasks into sim-
pler sub-tasks. In the second task, you will carry the passenger destination and capacity repre-
sentation from Problem 1 into a hierarchical model, specify primitive actions and decomposition
methods, construct an ordered task network, and design a service-order policy for passengers with
deadlines and time-dependent utility.
    Instructions: Work through this part in the 2 hierarchical.ipynb Jupyter notebook,
where step-by-step instructions will guide you in implementing and testing your hierarchical plan-
ning approach. You will directly implement your code solutions in 2 hierarchical solution.py.
Primitive actions, HTN methods, and the ordered initial task network are worth 1 point each. Solv-
ability with successful independent replay is worth 3 points, averaged across various test configu-
rations. Plan quality contributes the remaining 2 points and is based only on the normalized total
utility, for 8 points in total. Test configurations scale up to 10 passengers with a hard 10-second
per-case execution limit, as described in the notebook.

Problem 3: Free-form Planning (Optional, 2 Bonus Points)
The optional third task keeps the same passenger-request schema, capacity batching, timing model,
and utility function as Problem 2, but removes the required HTN representation. It tests on scenar-
ios with more passengers and uses a hard two-second limit for each case. You may use any finite
algorithm to choose the service order; passengers do not walk or change queues.
    Instructions: Complete 3 freeform planning.ipynb. You will implement the code
solutions in the corresponding python script 3 freeform planning solution.py. The
bonus is worth at most 2 points. Bonus points earned will fill in any points lost in Problems 1 and
2, with the final total assignment grade capped at 10 points. Twenty equally weighted hidden test
cases are used, and each case earns 0.1 point when a valid order attains at least 98% of the optimal
total utility within the hard two-second limit. Faster accepted solutions do not receive extra credit.
