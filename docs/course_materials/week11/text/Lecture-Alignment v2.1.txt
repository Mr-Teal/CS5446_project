Recall: Solving Sequential Decision Problem
• Decision Problem or Model
     • Appropriate abstraction of states, actions, uncertain effects, and goals (wrt costs and
       values or preferences) and time horizon + observations (through sensing)
• Decision Algorithm
     • Input: a problem
     • Output: an optimal solution over time horizon
• Decision Solution
     • An action sequence or solution from an initial state to the goal state(s)
          • An optimal action sequence; OR
          • An optimal policy that specifies “best” action in each state wrt to costs or values or preferences
     • (Optional) A goal state that satisfies certain properties

Theoretical Foundations
• Rational Decision Making: Solving Sequential Decision Problems
     • Combine beliefs, preferences, and decision processes for action selection to
       maximize expected utility, subject to constraints.

• Belief–Desire–Intention (BDI)
     • Beliefs → World information: observations, retrieval, memory, world models
     • Desires → Goals and desired outcomes: human preferences, reward models
     • Intentions → Committed goals and plans: planning, policy generation, tool use
• BDI provides a framework for goal-directed agents

                                           Refs: Bratman (1987); Rao & Georgeff (1991)

    Model Creation / Grounding ↔ Sense
    • Interpret observations; retrieve knowledge (RAG); support world-model creation & refinement.
    • Use predictive models or simulators to estimate outcomes.

    • Propose multi-step plans and subgoals (CoT/ToT).

    • Apply permissions, guardrails, and logging.
    Evaluator / Critic ↔ Plan / Learn
    • Evaluate plans and outcomes using external checks and human/AI feedback.
    • Revise plans and memory

     • Supervised fine tuning (SFT):
       Learn instruction-following behavior from demonstrations.
     • RL with human feedback (RLHF):

     • From demonstration-based learning to preference-based optimization using human or AI feedback.

Chain of Thought (CoT) Reasoning
• Core Idea
     • Generate intermediate reasoning steps before a final answer.
                             𝑦 = 𝑟4 , 𝑟5 , … , 𝑟6 , 𝑎 ∼ 𝜋' ⋅∣ 𝑥
     • where 𝑟7 are generated reasoning steps and 𝑎 is the final answer.
• Benefits
     • Supports structured, multi-step reasoning.
     • Enables review and critique of generated steps.
• Example:
     • Prompt: "If there are 3 apples, and you take away 2, how many apples do you have?"
• Limitation:
     • Generated reasoning may not faithfully reflect the model's internal reasoning.

CoT Extensions
• Self-Consistency
     • Sample multiple CoT paths and aggregate final answers.
• Program-of-Thought (PoT)
     • Generate executable code to perform computations.
• Step-Level Supervision
     • Evaluate intermediate reasoning steps using feedback or rewards.
     • Use these signals for process evaluation or learning.
• Key Distinction:
     • Self-consistency and PoT support decision-time reasoning; step-

Notes: Self-Rewarding Language Models (SRLMs)
• Core Idea
     • The model evaluates its own generated responses using LLM-as-a-Judge to guide iterative learning.
• Mechanism
     • Generate responses → Self-evaluate → Construct preference pairs → Update with DPO → Repeat.
     • LLM-as-a-Judge scores response quality using a rubric, e.g., relevance, usefulness, clarity.
