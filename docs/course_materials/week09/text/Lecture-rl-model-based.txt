Model-Based Reinforcement Learning                                                                      6
Notes: Why Model-based RL?
• Benefits
    • Real interaction may be expensive or risky.
         • Reuse real experience through model learning and planning.
         • Generate simulated experience without additional interaction.
    • Some decisions benefit from reasoning before acting.
         • Predict possible future outcomes and plan before executing an action.
• Challenges
    • Learning and using the model costs computation.
    • Model errors introduce model bias.
    • Planning may exploit systematic model errors.

Notes: From Model Learning to Planning
• Goal: use the learned model to improve the policy/value.
• A learned model can be used in three main ways:
    • Direct model solving
        Solve the learned MDP using dynamic programming or Bellman optimization
    • Sampling-based planning
        Simulate possible futures to improve value estimates or guide action selection.
    • Integrated learning and planning
        Learn directly from real experience and use the model for additional planning updates.
• Key idea:
    • Model learning provides predictions
    • Planning and learning use those predictions to improve decisions.

Notes: From Background to Decision-Time Planning

• Background planning
    • Use model-generated experience to improve value/policy over many states.
    • Example: Q-planning.
• Decision-time planning
    • Focus computation on the current state.
    • Look ahead using the model.
    • Choose an action, observe the next state, and plan again.
    • Example: Monte Carlo Tree Search (MCTS), model predictive control (MPC)
• Key idea:
    • Spend planning effort where it matters now.

Model-Based Reinforcement Learning                                               32
Monte Carlo Tree Search with Learned Models
• MCTS: explore possible futures from the current state.
    • Selection: follow the tree policy to a promising branch.
    • Expansion: use the model to generate a successor state (or latent state) and reward.
    • Simulation/Evaluation: estimate the value of the new leaf using a rollout or value function.
    • Backup: propagate the return/value up the tree.
• Learned components can include:
    • Model: transitions and rewards.
    • Value function: leaf evaluation.
    • Policy: guides search.
• Key idea:
    • Use model simulation to improve the current decision.

Model-Based Reinforcement Learning                                                                     47
Representative World Model Approaches
• Learned latent world models
    • DreamerV3 (2025): Learns policy and value functions from imagined latent trajectories.
    • MuZero (2020): Uses MCTS for decision-time planning with a learned latent model.
    • TD-MPC2 (2024): Uses MPC for decision-time planning with a learned latent model.
• Connections to earlier methods
    • MCTS → MuZero: Tree search with learned dynamics.
    • MPC → TD-MPC2: Receding-horizon planning with learned dynamics.
• Key distinction:

Model Error and Limitations
• Model error
    • Learned models, including latent models, are approximate.
    • Errors can accumulate over multi-step predictions or search.
    • Planners or policies may exploit systematic errors.
• Main trade-off
    • "More model use" ⟹ "potentially less real interaction, but greater exposure to model bias."
• Common responses
    • Use short rollouts or learned terminal/leaf values (e.g., MBPO, TD-MPC2, MuZero).
    • Replan after new real observations (e.g., TD-MPC2, MuZero).
    • Update the model with fresh real experience (e.g., DreamerV3, TD-MPC2, MuZero).
    • Preserve decision-relevant information in learned representations (e.g., MuZero, TD-MPC2).
    • Model uncertainty explicitly (e.g., PETS).
Model-Based Reinforcement Learning                                                                  59
Summary
• Model Learning
    • Models may be given or learned.
    • Learned models predict dynamics, rewards, or latent representations.
    • Useful models need to preserve decision-relevant information, not every observable detail.
• Using models
    • Direct solving, simulated learning, search, imagination, or decision-time planning.
• Main lessons
    • Model-based RL connects learning and planning.
    • Model-generated experience can reduce real interaction at the cost of computation.
    • Longer model rollouts increase exposure to model error.
    • Short rollouts and replanning can limit accumulated error.
    • Modern methods often operate in learned latent representations.
• Key idea
    • A model need not predict everything accurately, but it must be accurate enough for the decisions it supports.
