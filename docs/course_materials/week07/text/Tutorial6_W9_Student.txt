Problem 2: Persy the Mars Rover uses MCTS
Mission context. Persy the Mars Rover is exploring a Martian delta to search for hydrated minerals.
The state is described by M variables (e.g., soil type, slope, dust load, battery), each with n possible
values. At each step, Persy can either:

    • Move to an adjacent grid cell, or

    • Scan the current location

Each action leads to two possible stochastic outcomes.

a) What is the size of the state space of this MDP? Can this MDP be solved efficiently with value
   iteration as M grows?

b) A search tree of depth D (i.e., D actions from root to leaf) is built from an initial state. Each
   action has two possible outcomes. What is the size of this tree (number of nodes and edges) in
   big-O notation? Why is online search more feasible if D is a small fixed constant?

c) Instead of expanding the full tree, Persy uses Monte Carlo Tree Search (MCTS) up to depth
   D for T trials. What is the typical size of the grown search tree and the number of simulation
   steps?

d) Describe the four phases of MCTS (selection, expansion, simulation, backpropagation) when
   used on an MDP. Which phase applies an exploration–exploitation rule, and which phase reuses
   past statistics?

e) At one state, Persy can Move or Scan. After 16 MCTS trials:

       • Move: tried 8 times, reward 1 in 4 trials (4/8)
       • Scan: tried 8 times, reward 1 in all 8 trials (8/8)

   Using the UCT formula with c = 1 and log base 2, compute the selection scores for each action.
   Which action will be chosen?

f) Suppose Scan is selected and one new rollout from its child state returns G = 0.6. Before the
   new trial, N (s, Scan) = 8 and Q̂(s, Scan) = 1.0. Show the updated visit count and average
   return estimate after backpropagation.

Problem 3: Imitation Learning with Persy the Mars Rover
Persy the Mars Rover is learning to navigate safely on the Martian surface. We are given a set of
expert demonstrations from human teleoperators showing how to choose actions (move, turn,
sample, wait) in various states of the terrain (slope, rock density, battery level, etc.).
    We want to train Persy using imitation learning (behavioral cloning) so it can act autonomously.
    We define a feature vector f (s) for each state s and represent the policy as a softmax distribu-
tion:

                                     π(a | s) ∝ exp(θa · f (s))

  (a) Why might we want to use this feature-based softmax approach over a tabular policy estima-
      tion approach that directly estimates a separate probability Pr(a | s) for every state–action
      pair?

  (b) Behavioral cloning often suffers from compounding errors when deployed. Explain why this
      happens, and how the DAgger (Dataset Aggregation) algorithm helps address it.

  (c) Do you think human demonstration is a good approach in this case? Why or why not?
