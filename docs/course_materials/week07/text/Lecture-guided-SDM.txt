Main Approach
• Large Markov decision process (MDP):
    • State space grows exponentially
    • Offline methods (Value Iteration, Policy Iteration) are infeasible
• Solution:
    • Search forward (build search tree) only from current state
    • Plan just enough to pick the next good action
    • Avoid full offline policy computation

Rollout: Strengths and Limitations
• Strengths
    • Simple: simulate and average returns
    • Effective: improves over rollout policy
    • Flexible: works even with random policy
    • Parallelizable: independent simulations
• Limitations
    • High computation per decision
    • Accuracy depends on rollout policy quality
    • Limited by decision-time constraints

Decision-Time and Demo-Based Planning              15
From Rollout to Monte Carlo Tree Search
• Rollout:
    • Simulate many trajectories from current state
    • Average returns for each action
    • Choose best action (one-step policy improvement)
• Monte Carlo Tree Search (MCTS):
    • Extends rollout with tree expansion and guided sampling
    • Balances exploration vs exploitation (e.g., Upper Confidence Bound)
    • Reuses rollout statistics across decisions
    • Enabled breakthroughs (e.g., AlphaGo)
• Key Insight:
    • MCTS = Rollouts + Smart Tree Search → scalable decision-time planning

Exercise
• So far, we have left action selection at a node undefined.
• Q: How should we select an action at a node 𝑛?
    • Assume a deterministic Markov decision process (MDP):
    • 𝑃(𝑠 $ |𝑠, 𝑎) is deterministic.
    • Each node 𝑛 corresponds to a state 𝑠.
• What if we use a deterministic function 𝑓 𝑠 to pick the action at each node (except the root)?
    • Then 𝐴 𝑠 = 𝑓 𝑠 is just a fixed policy.
    • If we also use 𝑓 𝑠 as the rollout policy at the leaves, this becomes plain rollout, offering no improvement
      over rollout.
• Better approach:
    • At each node, explore actions first, then gradually shift to more greedy (exploit) choices , e.g., using:
         • Upper Confidence Bound (UCB1)
         • 𝜖-greedy or softmax selection.

Summary: Decision-Time Planning
• Core Idea:
    • Plan at runtime by simulating possible futures from the current state,
      instead of solving the full MDP offline.
• When Effective:
    • Large branching factors
    • Deep search trees
    • Simulator/model available
    • Limited real-time budget
• Key Techniques:
    • Online search: build shallow trees each step
    • Monte Carlo Tree Search (MCTS): combine tree search + rollouts
    • Upper Confidence Bound (UCT): balances exploration vs exploitation

Pitfalls: Why Supervised Learning Fails
• Supervised Learning Assumption:
    • Training and test data come from the same distribution (i.i.d.)
    • Imitation Learning Reality:
    • Learner's actions change future states → breaks i.i.d. assumption
Key Challenges:
• Distribution Mismatch:
    • States visited during execution differ from expert demonstrations

• Compounding Errors:
    • Early mistakes lead to drift into unfamiliar states → more errors
• Limited Generalization:
    • Learner may fail to recover in unseen or rare states

DAgger (Dataset Aggregation)
• Iterative improvement over BC:
    1.     Train policy on expert demos
    2.     Execute current policy → collect visited states
    3.     Ask expert to label those states
    4.     Aggregate new data and retrain
• Key ideas:
    • Trains on states the learner actually visits
    • Reduces distribution mismatch and improves robustness
• Variants:
    • SafeDAgger (safety), DART/SHIV (less expert input)
    • HG-DAgger (generalization), Agnostic IIL (handles imperfect experts)

Summary: Imitation Learning
• Goal:
    • Learn behavior from expert actions (no rewards or optimality)
• Pros:
    • Simple, effective for automated tasks
• Cons:
    • Prone to compounding errors; limited to expert performance – no notion of
      reward or optimality
• Main techniques:
    • Behavioral cloning: supervised policy learning
    • DAgger: iterative expert corrections
    • GAIL: adversarial approach (policy vs discriminator)

Summary: Beyond Full Offline Planning
and Reinforcement Learning
• Decision-time planning
    • Simulate forward at runtime from the current state
    • Build shallow search trees on demand
    • Avoid solving the full MDP or training a full RL policy offline
• Demonstration-based planning
    • Learn from expert behavior before runtime
    • Derive policies from demonstrations (e.g. Imitation Learning)
    • Reduces data and compute cost compared to full RL training
• Shared Advantage
    • More sample- and compute-efficient than full offline planning or fully trained RL
    • Practical for real-time and resource-limited settings
